# 교안 L7 장애 주입 (PC 모의) · 2026-11-06

왜 하나: 교안 최종 제출 항목 중 장애 대응만 시험하지 않았다. 카메라 · 프로세스 · 입력에 문제가 생겼을 때 인지 노드가 오래된 결과를 내지 않고, 죽지 않고, 스스로 돌아오는지 본다.

**모의 시험이다.** PC에서 실제 인지 노드를 띄우고, 입력은 Isaac 렌더 영상(B0 판정 렌더)을 벽시계 시각으로 15 Hz 재생한다. 실물 카메라 · Jetson · 제어기는 쓰지 않는다.

- 대상: `261105_2015_yolo_e3/install`. perception · perception_survey · robot_interfaces 소스와 perception.yaml 이 origin/dev(ae7c7e2)와 같음을 확인했다.
- 엔진: E3 480 · 384 FP16 PC 빌드(`261105_2015_yolo_e3/trt`). GPU 잠금 안에서 돌린다.
- 설정: 사본에서 `image_qos: reliable`(이제까지의 재생 시험과 같음)과 엔진 경로만 바꾼다.
- 기준은 사용자가 Claude 에게 맡겼다(2026-11-06, 검토 없이 진행). 이미 있는 값에서 가져왔다: 받는 쪽 300 ms 규칙, 인지 P5(끊기면 0.3 s 안에 멈춤, 같은 stamp 에 새 결과 없음), 부하 판정(300 ms 초과 ≤ 0.5 %).
- 복구 0.5 s 는 새로 정한 값이다. 15 Hz 처리 몇 번과 전달 여유를 합쳐 잡았다.

## 범위 밖

- GPU · CPU 실제 포화: 같은 PC 에서 다른 세션의 시험이 돌아 일부러 포화시키지 않는다. F10 의 일시 정지로 모사만 한다.
- 교안의 1시간 통합 시험, Jetson 에서의 반응 시간: 실측이라 하지 않는다.
- 제어기(mission · drive · manipulator)의 실제 반응: 띄우지 않는다. 코드에 있는 300 ms 규칙만 적는다.

## 도구 확인 (판정 아님, 2026-11-06 11:4x)

색 검출기로 GPU 없이 `tool_color/` 에서 F1~F11 을 끝까지 돌렸다(F12 는 엔진이 있어야 해서 판정 실행에서 처음 돈다). 고친 도구 결함 두 개:
- 팔 자세의 관절 수(7)가 D435 자세(8)와 달라 robot_state_publisher 가 상태를 버렸고, 팔 TF 가 끊겨 F7 결과가 0 이었다.
- 팔 영상은 촬영 시각 TF 를 기다리므로, 카메라 지연처럼 0.1 s 앞선 stamp 로 낸다. F7 · arm_short 의 복구 값에는 이 0.1 s 가 들어 있다.

## 이 시험으로 알게 된 것과 한계

- **해시 파일이 없으면 변조를 잡지 못한다.** `flip_nofile`(기록만): WARN 0, 14.67 Hz, 찾은 퍽 0. Jetson 에 해시 파일을 만들어야 효과가 있다. (2026-11-06 해시 파일은 만들었고, 해시 코드가 든 빌드를 Jetson 에 배포하기 전까지는 아직 동작하지 않는다.)
- 주 엔진이 실패하면 팔 엔진이 멀쩡해도 무시되고, 팔도 색 · 라벨 검출로 돈다(`arm.engine_path 는 … 무시` 로그). 엔진 실패 WARN 을 보면 기동을 멈추고 고쳐야 한다.
- 프로세스가 죽으면 자동 재시작이 없고 launch 도 끝나지 않는다. 사람이 재기동하고, 미션이 모드를 다시 보내야 한다. 재기동 뒤 미션 동작은 시험하지 않았다.
- 제어기 동작은 코드만 읽었다: mission `stale_timeout` 0.3 s, drive `stale_s` 0.3 s, 스킬 시간 초과. F5 의 받는 쪽 처리는 확인하지 않았다.
- 모의 입력(렌더 영상 한 장 반복, 15 Hz)이고 PC 다. Jetson 반응 시간, 실제 GPU · CPU 포화, 1시간 통합 시험은 하지 않았다.
- A1 · F1 회귀는 다시 돌리지 않았다. 바뀐 코드는 엔진을 읽을 때 한 번만 돌고, 해시 파일이 없으면 동작이 같다.
