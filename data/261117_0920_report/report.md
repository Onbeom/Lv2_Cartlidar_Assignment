### 3-3. 속도 제한을 이렇게 정한 이유 (사용자 지시로 꼭 넣음)
1. 처음에는 USD 의 관절 속도 한계(인수인계 임시값 바퀴 2.0 · 팔 0.5 rad/s)를 PhysX 가 적용하게 두었다.
2. 그런데 중력이 있으면 PhysX 속도 한계가 팔꿈치를 명령 반대로 보냈다(D3A). 그래서 **PhysX 한계를 끄고 제어기에서 목표 변화율을 제한**했다(v4). 실물 Dynamixel 의 Profile Velocity 와 같은 방식이다.
3. 한계값은 **ROBOTIS 공식 무부하 속도(11.1 V)** 로 정했다(v5): 바퀴 XM430-W210 70 rev/min = 7.3304 rad/s, 팔 XM430-W350 43 rev/min = 4.5029 rad/s. Velocity Limit 초기값(75.6 · 45.8 rev/min)보다 낮지만 11.1 V 에서 실제로 낼 수 있는 값이다. 집게는 환산식이 없어 0.01 m/s 를 유지했다.
4. 제어기 한계는 목표에만 걸리므로 실제 팔 속도 ≤ 4.9532 rad/s(× 1.1) 기준을 더했고(v6), 넘침은 팔 감쇠 조정으로 줄였다.
5. 증속 벨트 반영 뒤(261027_1530) 바퀴 한계는 10.995574 rad/s(70 rev/min × 1.5) 로 바꿨다.

### 4-1. Nav2 · 위치 추정 모의 (11-02 ~ 11-06) [모의]

- 지도 주의(사용자 지시로 꼭 넣음): SLAM 지도는 Isaac 세계(maze.usda)와 맞지만(중앙 0.0096 m), maze.usda 와 발제 SDF 는 동 · 북 벽에서 다르다(p95 0.0964 m, 최대 0.1429 m). 원인은 세계 모델이 둘인 것이다. map 만 바꾸고 loc_map 을 안 바꾸면 불일치가 생긴다.

### 4-2. cuVSLAM 과 Cartographer (실습 과정의 비교)
- cuVSLAM odom → Cartographer 결합은 실행 · 지도 저장은 됐지만 위치 정확도가 기준 미달이었다 [모의]: 위치 RMSE 밝음 0.203 → 0.293 m, 어두움 0.204 → 0.370 m(기준 0.05 m). 추적 lost 0 만으로 SLAM 성공이라 하지 않았다.

- 정리: Cartographer 는 라이다만으로 모의 · 실물 지도를 만들 수 있었고 설정 효과가 분명했다. cuVSLAM 은 이번 모의 조건에서는 정확도가 부족했다(실물 비교는 하지 않음).
