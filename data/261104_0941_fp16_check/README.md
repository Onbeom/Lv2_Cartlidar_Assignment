# 모델 D FP16 엔진 확인 (2026-11-04 09:41)

왜 하는가:
- 실물 부하 1단계(카메라 3대 + YOLO D FP32, 30분)에서 GPU 평균 53 %였다.
- 한 번 처리에 약 21 ms가 걸려, 15 Hz × 3대(초당 45번)로 추론 스레드가 1초 중 약 94 %를 썼다(`261103_1544_jetson_load/README.md`).
- SLAM(특히 GPU를 쓰는 cuVSLAM)을 더하기 전에, FP16으로 정확도는 그대로 두고 여유를 만들 수 있는지 본다.

방법(`pkg/fp16_check.py`, Jetson 시스템 python3 — tensorrt · cv2 · numpy만 씀):
- FP16 엔진: `trtexec --onnx=D --fp16`(FP16 허용 · 혼합 정밀도).
- FP32 엔진: 배포 중인 `~/yolo_D/deploy/yolo11n_task4_D_fp32_notf32.engine`.
- 두 엔진을 같은 장 1478장에 돌린다. 전처리 · 후처리는 배포 실행기 `trt_run.py`와 같다.
  - 판정 영상 장면 1275장: 커튼 앞 · 뒤 270 + 270, 오전 앞 · 뒤 270 + 270, Arducam 195.
  - 옛 실물 평가 203장: 켜진 신호등 장면 포함.
  - 검출은 conf 0.10 · NMS 0.45로 저장하고, 판정은 PC의 `judge.py`로 한다. 설정은 D 고정 때와 같다(쌓인 퍽 뺌, 뒤는 있다/없다).
- 속도: trtexec 순수 GPU 시간과 파이썬 한 장 처리(H2D + 실행 + D2H) 시간.
