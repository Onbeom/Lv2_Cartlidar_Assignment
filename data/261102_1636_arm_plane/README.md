# 261102_1636 팔 카메라 평면 교차 오프라인 평가 (도구 확인, 모의)

목적: 손목 Arducam(깊이 없음)의 박스 중심 시선을 알려진 수평면과 교차해, 깊이 없이 퍽 위치(집게까지 거리)를 얼마나 맞히는지 본다.
자료: A1 모의 렌더 validation_v12(모델 261028, 노이즈 없음)와 그 재생에서 perception_node가 낸 arm_offset 및 D435 추적 목표(seed_object). 오차는 퍽 중심의 수평 오차다.

| 방식 | 예상 | 결과 (중앙 / p95 / 최대, mm) |
|---|---|---|
| 평면 = 정답 중심 높이 (`eval_plane.py`) | 5 mm 안팎. 박스 중심과 퍽 중심이 조금 어긋남 | 3.4 / 11.1 / 18.2 (n 228) |
| 평면 = D435 목표 z (`eval_plane.py`) | 정답 높이보다 나쁨. D435 z 오차가 비스듬한 시선에서 커짐 | 9.5 / 19.7 / 25.9 |
| 위 두 경우 + 퍽 형상 보정 (`eval_shape.py`, 서 있는 퍽 160) | 수 mm 개선 | 정답 높이: 3.7→3.0 / 9.1→8.8. D435 높이: 14.2→10.7 / 20.1→16.4 (개선 작음) |
| 높이 고르기: 받침 {0, 0.07} + 반높이 {0.015, 0.03} 중 D435 z에 가장 가까운 값 (`eval_snap.py`) | 정답 높이 경우와 같아짐 | 높이 고르기 틀림 0/194. 3.6 / 10.4 / 18.2 |
| 비교: D435 추적 위치 그대로 | 모의 깊이는 잡음이 없어 매우 작음 | 2.5 / 3.0 / 3.0 (n 194) |

- 따로 잰 값:
  - 정답 상자 중심 + 정답 높이: 3.4 / 7.2 / 18.3. 기하만으로도 남는 오차다.
  - 검출 상자 중심과 정답 상자 중심의 차이: 중앙 1.2 px, p95 10.1 px.
  - D435 목표 z − 정답 중심 높이: 중앙 −4.7 mm.
- 카메라와 퍽 사이 거리는 0.32~0.55 m다(A1 '보임' 단계). 집을 때처럼 더 가까우면 오차는 거리에 비례해 줄어들 것으로 예상하지만, 재지는 않았다.
- 해석: 모의에서는 D435 추적 위치가 평면 교차보다 정확하다(모의 깊이에 잡음과 외부 보정 오차가 없음). 평면 교차가 이득인지는 실물 D435 오차와 접근 중 odom 누적에 달려 있고, 모의로는 판단할 수 없다.

## 노드 구현 뒤 모의 재생 (11-02 밤, 사용자 지시 "예비로 구현")

- 평면 높이는 D435 목표가 있으면 받침·반높이 목록에서 고르고, 목표를 잠근 동안 유지한다. 그래서 D435가 놓쳐도 팔 카메라만으로 낸다. 화면 가장자리에 잘린 박스로는 내지 않는다.

- 상황: dev에서 kanichong이 `/arm_range`(팔 끝 → 퍽 표면, 출처 ① 태그 ② D435 보유 점, arm_range.hpp)를 만들었고 manipulator가 그것을 쓴다(#37). 주행 정렬은 `/tfmini/range`를 쓴다.
