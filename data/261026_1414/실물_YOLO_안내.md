# 실물 퍽 YOLO 자료 만들기 안내 (사용자가 할 일)

순서: 촬영 → 시뮬레이션 모델로 자동 라벨(초안) → 사람이 고침 → 묶음 단위로 학습 · 평가 나누기 → 시뮬레이션 자료와 섞어 미세 조정 → 실물 평가.
시뮬레이션 모델: `261026_1414/runs/<이름>/weights/best.pt`(학습이 끝나면 이름을 STATUS_yolo.md 에 적음).
클래스(6개, 번호 = 모양 × 3 + 색): 0 red_cylinder · 1 green_cylinder · 2 blue_cylinder(비움) · 3 red_cuboid · 4 green_cuboid · 5 blue_cuboid(비움).
실물 퍽은 빨강 · 초록뿐이라 2 · 5번 상자는 없어야 한다. 신호등(빨강 · 노랑 · 초록)은 YOLO 대상이 아니다(라벨을 달지 않음, HSV 가 판별).

## 1. 촬영 (필수)

촬영 목록은 인지 파트 R3 설계 세션 안내(STATUS.md 5-1)와 같다. 촬영 도구와 저장 형식은 `cartlidar/PHOTO_GUIDE.md` 를 따른다.

| 항목 | 내용 |
|---|---|
| 카메라 | 로봇에 단 앞 D435(640 × 480, 30 fps). 장착 높이 · 기울기를 실제 운용과 같게(시뮬레이션이 URDF 장착 자세로 학습했으므로 같은 시점일수록 잘 맞음) |
| 퍽 | 빨강 · 초록 × 원기둥 · 직육면체 4종 |
| 배치 | 선반 위(서 있음) · 바닥(누움 포함). 한 장면에 여러 퍽을 섞고 서로 가리게 |
| 거리 · 방향 | base_footprint → 퍽 0.3 · 0.5 · 0.8 · 1.0 m × 정면 · 좌우 약 30° |
| 조명 | 낮조명 on · off 2가지 |
| 양 | 장면(묶음) 20개 이상, 컬러 200~300장, 깊이도 같이 저장 |
| 노출 | **운용과 같은 고정 수동 노출로 찍는다**(운용은 노출을 바꾸지 않고 낮은 노출 하나로 씀, 사용자 2026-10-26). 운용 노출 · gain 값이 정해진 뒤 퍽 자료를 찍는다. 도구가 metadata.json 에 노출 · gain 을 저장하고, 묶음 label 에도 `exp30_gain16` 처럼 적는다 |
| 빈 장면 · 반사 (선택 · 권장) | 퍽 없는 선반 · 바닥 · 신호등 켜짐 장면, 퍽이 아크릴 벽판에 비치는 장면 몇 장. 헛검출을 줄이는 데 쓴다(빈 장면은 라벨 파일을 빈 채로, 반사된 모습에는 상자를 달지 않음). 시뮬레이션 평가에서 벽판에 비친 퍽을 퍽으로 낸 경우가 1건 있었음 |

- 사람 얼굴이 찍힌 사진은 학습 자료 · 저장소에 넣지 않는다. 찍혔으면 그 장은 빼거나 얼굴 부분을 지운다(필수).
- label 예: `pucks_shelf_mix_050cm_light_on_ae_on`. 같은 배치를 거리만 바꿔 찍으면 한 묶음으로 본다(그래야 학습 · 평가가 섞이지 않음).

촬영 (PC, 카메라 연결된 컴퓨터) (필수):

```bash
bash /home/pa4/git/lv2_next_module/cartlidar/run_capture.sh --front 261822072247 --rear 261822079801 --label pucks_shelf_mix_050cm_light_on_ae_on
```

(앞 · 뒤 시리얼 짝은 실물에서 확인해서 맞게 넣는다. 화면 클릭 후 `s` 저장, `q` 종료.)

## 2. 자동 라벨 초안 (필수, 제가 돌려도 됨)

묶음 하나씩, 묶음 이름을 붙여 돌린다. 앞 카메라 사진만 쓰려면 촬영 폴더 안의 앞 카메라 하위 폴더를 `--src` 로 준다.

자동 라벨 (PC) (필수):

```bash
~/yolo-venv/bin/python /home/pa4/git/lv2_next_module/Cartlidar/yolo/auto_label.py --model /home/pa4/git/lv2_next_module/261026_1414/runs/sim_v1/weights/best.pt --src /home/pa4/git/lv2_next_module/cartlidar/photo --only-color-png --batch b01_shelf_mix --out /home/pa4/git/lv2_next_module/261026_1414/real_labels
```

- 결과: `real_labels/images/`, `real_labels/labels/`(YOLO 형식 초안), `classes.txt`, `auto_label.json`(장마다 상자 수 · 신뢰도, `checked: false`).
- 신뢰도 문턱을 낮게(0.10) 두어 지울 상자가 많고 놓친 퍽이 적게 했다. 지우기가 새로 그리기보다 빠르다.

## 3. 라벨 고치기 (필수, 사람)

도구: `Cartlidar/yolo/fix_labels.py`(설치 없이 `~/yolo-venv` 로 돈다. labelImg 는 Python 3.12 에서 그림 그릴 때 죽는 경우가 알려져 있어 쓰지 않음).

라벨 고치기 (PC) (필수):

```bash
~/yolo-venv/bin/python /home/pa4/git/lv2_next_module/Cartlidar/yolo/fix_labels.py --dir /home/pa4/git/lv2_next_module/261026_1414/real_labels
```

- 아직 안 본 장부터 2배 크기로 연다. 묶음 하나만: `--batch r01`. 다 본 장까지 다시: `--all`.
- 마우스: 빈 곳을 왼쪽으로 끌기 = 새 상자, 상자 왼쪽 클릭 = 고르기(하늘색), 고른 상자의 모서리 끌기 = 크기 조절, 상자 오른쪽 클릭 = 지우기.
- 키: `1` 빨강 원기둥 · `2` 초록 원기둥 · `3` 빨강 직육면체 · `4` 초록 직육면체(고른 상자의 클래스를 바꾸고, 다음 새 상자의 클래스도 됨),
  `d` 고른 상자 지우기 · `z` 되돌리기 · `e` 이 장 상자 모두 지우기 · `b` 화면만 밝게(어두운 사진용),
  `스페이스` 저장하고 '다 봄' 표시 후 다음 장 · `p` 앞 장 · `q` 저장하고 끝. 얇은 선 = 원기둥, 굵은 선 = 직육면체.
- 저장할 때 처음 초안과 비교한 지움 · 추가 · 클래스 바꿈 · 크기 고침 수가 `auto_label.json` 에 남는다(시뮬레이션 모델이 실물에서 얼마나 틀렸는지 대략 보는 데 씀).

고치는 규칙:
1. 퍽마다 상자 하나, **보이는 부분**에 딱 맞게(시뮬레이션 라벨과 같은 규칙: 가려진 부분은 넣지 않음).
2. 클래스 = 색 × 모양. 색 · 모양 중 하나라도 틀리면 고친다.
3. 너무 많이 가려 사람도 모양을 알 수 없는 퍽(대략 보이는 겉면 20 % 미만)은 상자를 지운다(시뮬레이션 `--min-vis 0.2` 와 같음).
4. 퍽이 아닌 곳(신호등 · 상자 · 벽판 반사 · 의자 · 바닥 등)에 붙은 상자는 모두 지운다.
5. 퍽인데 상자가 없으면 그린다.

## 4. 학습 · 평가 나누기 (필수)

- **묶음 단위로** 나눈다. 같은 배치에서 거리만 바꾼 사진이 학습과 평가에 같이 들어가면 평가가 부풀려진다.
- 제안: 묶음의 약 70 % 학습 · 10 % 검증 · 20 % 평가. 평가 묶음은 낮조명 on · off, 선반 · 바닥, 0.3~1.0 m 를 고루 갖게 고른다.
- 평가 묶음은 학습에 절대 쓰지 않는다.

## 5. 미세 조정과 실물 평가 (제가 함, 판정 기준은 그때 확인받음)

- 시뮬레이션 모델(best.pt)에서 시작해 실물 학습 묶음 + 시뮬레이션 학습 자료 일부를 섞어 학습한다(실물만 쓰면 수가 적어 과적합되기 쉬움).
- 실물 평가 판정 기준은 아직 없다(인지 판정 기준 v1: "실물 시험은 나중에 따로 정한다"). 제안 방향: 시뮬레이션 R4 와 같은 셈(1.0 m 이내, 짝 지은 퍽 중 모양 ≥ 95 %, 검출 · 색은 기록) — 시작 전에 확인받는다.
- 실물에서는 base_footprint 거리를 렌더 정답처럼 알 수 없으므로, 거리는 촬영 label 의 대략 거리(또는 깊이 영상 중앙값)로 나눈다.
- Jetson 에서 쓰려면 ONNX 로 내보낸 뒤 Jetson 에서 `trtexec` 로 엔진을 만든다(팀 perception `trt_detector.cpp` 는 YOLOv8 출력 형식을 읽고, YOLO11 출력 형식도 같다 — 실제 동작은 아직 확인 안 함).
