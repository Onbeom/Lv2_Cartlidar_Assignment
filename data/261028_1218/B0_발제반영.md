## ① 인지 세션에 알릴 것 (퍽 병합 세션에 보냄)

- 바코드는 출발 자세 앞 D435 화면 밖(올려본각 −3.0°, 화면 위끝 −13.6°) → 팔 Arducam 으로 읽음(사용자 결정). 판에 바짝(차체 중심 x 약 0.32 m) 붙어 0.10~0.15 m 거리, 640 × 480 이면 모듈당 0.6~0.9 px → 바코드 때만 고해상도 한 장(사용자 예외 허용). 판 앞 이동은 규칙상 허용(사용자 확인).
- 바코드는 정렬 방향만(P2-01 · 03 오름, P2-02 · 04 내림), 퍽 색 · 모양 수는 안 줌 → 퍽 조사 표(아래 ④)가 필요.
- 신호는 무한 반복(12회 → 3 초 소등 → 다시). 팀 `signal_sequence.hpp` 는 이미 텀(꺼짐 중앙값 × 2 = 2 s 넘는 꺼짐)으로 주기를 끊고 같은 12개가 2번이면 CONFIRMED, 다르면 MISMATCH 뒤 다음 주기를 계속 봄 → **코드 변경 필요 없음**. 단위 시험 U1(무작위 1000, 텀 ≥ 3 × 꺼짐)이 발제 값(1 · 1 · 3 s)을 덮음.
  mission 쪽 할 일: CONFIRMED 를 기다리는 시간 상한(예: 3 주기 ≈ 81 s)과 넘으면 오류 기록 · 정지 — 발제 오류 규칙.
- 재검증 점수는 '새 관측의 장소별 ID · 위치' → 놓은 뒤 장소마다 퍽 ID(윗면 태그)를 다시 읽어야 함. 목표 표를 복사한 로그는 0점.
- 퍽은 모두 70 mm 박스 위에 서 있음(윗면 130 mm). 바닥 · 누운 퍽 없음, 쌓기 금지. 시작 박스 중심 x ± 40 mm 에 2개.
- 장소 태그: L1 = 12, L2 = 13, L3 = 14(그림), 박스 접근 방향 수직 면, 중심 높이 35 mm.
- 새 맵: 발제 2쪽 그림이 곧 현재 맵(벽 · 기둥 · 박스 위치 유지 표기). 아래 ⑤ 초안.

## ③ 신호등 SL1 + 발제 도전 A (승인 전)

- SL1(승인됨 10-27): 영상 프레임 단위로 방식 A(팀 HSV) · B(신호등 상자 안 HSV) · C(칸 위치 밝기) 비교, 통과 = 상태 맞음 ≥ 99 % · 다른 색 ≤ 0.5 % · 신호등 밖 헛덩어리 장당 ≤ 0.01. 그대로 둠.
- 도전 A 를 SL1 의 2단계로 붙임: 기존 설정(팀 현재 HSV · 노출) vs 개선 설정(SL1 에서 통과한 방식 · 노출).
  - 바꾸는 변수 = **조명** 하나(방 조명 켬 / 끔 / 켬 + 옆 강한 조명). 이유: 경기 관측 거리는 출발 자세로 고정(신호등–로봇 중심 654 mm)이라 거리보다 조명이 경기 날 바뀌는 값.
  - 신호가 무한 반복이므로 조건마다 같은 12회 시퀀스를 **한 번 연속 녹화(6 주기 이상, 약 3 분)** 하고 앞 5 주기를 5 회로 씀. 같은 영상을 두 설정에 재생 → 2 × 3 × 5 = 30 회 · 360 점멸.
  - 기록(실험 전): 노출 · gain · WB · 거리 · 시퀀스 · 정답. 실물 실시간과 녹화 재생 결과는 따로 적음.
  - 측정: 주기마다 읽은 12 개(묶음 기록) → 순서 정확도(맞은 점멸/전체), 횟수 완전 일치율(세 횟수 모두 맞은 회/전체), 오류 정지(12 개 아님 · 불명 색), 처리 지연(텀 끝 → 확정).
  - 판정(제안): 개선 설정이 세 조건 모두 횟수 완전 일치 5/5 · 순서 정확도 60/60, 그리고 두 주기 확정 로직으로 **틀린 확정 0**. 개선이 안 되면 원인 · 한계를 기록(발제상 실험 완료).

| 측정 | 예상 |
|---|---|
| 기존 · 방 조명 켬 · 순서 정확도 | 60/60 근처 — 10-26 cam1 노출 30 · WB 자동 · 벽 있는 곳에서 노랑이 빨강으로 안 섞였음 |
| 기존 · 방 조명 끔 · 순서 정확도 | < 60/60 — 노출 10~30 에서 노랑 칸 H 9~11 이 빨강 범위(H ≤ 10)에 걸침(10-26 훑기) |
| 개선 · 세 조건 · 횟수 완전 일치 | 5/5 — 노출 · WB 를 SL1 기준(제 색 ≥ 30, 다른 색 ≤ 10 %)으로 고른 값 |
| 두 주기 확정 · 틀린 확정 | 0 — 한 주기 오독은 두 주기가 달라 MISMATCH 로 남고 다음 주기를 봄 |
| 처리 지연(텀 끝 → 확정) | 0.1~0.3 s — 다수결 3 프레임 + 텀 판정(2 s 넘는 꺼짐) 뒤 바로 |

필요한 것(사용자): 신호등의 12회 시퀀스를 고정값으로 정할 수 있는지(도전 A 는 같은 시퀀스 5 회).

## ④ 퍽 조사 표와 할당

조사 표 `puck_survey.json`(조사가 끝나면 한 번 쓰고, 할당은 이 표만 읽음):

```json
{"stamp": "...", "frame": "map(mm, 발제 원점)",
 "boxes": [{"box": 1, "center_mm": [1468, 950], "yaw_deg": 7.5, "yaw_measured": true}],
 "slots": [{"box": 1, "side": -1, "x_mm": 1428.3, "y_mm": 944.8, "measured": true,
            "present": true, "color": "red", "shape": "cuboid", "pose": "lying", "yaw_deg": 32.0,
            "id": 3, "conf": {"color": 0.99, "shape": 0.97, "id": 1.0},
            "seen_by": ["front_d435", "arm"], "n_obs": 14}]}
```

- 자리는 12칸(박스 6 × 2)이지만 **박스가 벽과 평행하지 않게 돌아가 놓일 수 있음**(사용자 2026-10-28, 인지 세션 전달) → 칸 좌표는 박스 중심 + 박스 yaw 로 돌린 (±40, 0) 을 시작값으로 두고 관측 위치로 바꿈.
- **원기둥은 항상 서 있고 직육면체는 누울 수 있음**(발제 '윗면 130 mm' 와 다름) → `pose` standing | lying, 누운 직육면체는 윗면 높이 100 mm · 긴 축 yaw 기록. 직육면체는 6면 모두 태그(원기둥은 윗면 · 아랫면만, 사용자 2026-10-28) → 누워도 위를 보는 면 태그로 팔 카메라가 ID 를 읽음(옆면 태그 크기는 확인 전). 모양 판정 · 할당 규칙은 그대로(누워도 직육면체).
- 관측은 '있음 · 색 · 모양 · 자세 · ID' 를 채우는 일. 색 · 모양 = 앞 D435(YOLO 4클래스 + HSV 교차), ID = 윗면 태그(팔 카메라).
- 어느 칸이든 색 · 모양 · ID 가 불명이거나 ID 가 겹치면 할당 전에 그 칸만 다시 봄 → 그래도 안 되면 오류 기록 · 정지(발제 오류 규칙, 임의 추정 금지).
- 할당(시제품 `alloc_proto.py`, 도구 확인): Y 를 뺀 나머지가 R · G 와 정확히 같아야 하므로 **Y 에 쓸 빨강 수 = 빨강 전체 − R, 초록 수 = 초록 전체 − G 로 정해짐**. 그 수만큼 같은 모양(원기둥 → 직육면체 순으로 시도)이 있으면 풀림. 무작위 13 887 건에서 전수 탐색과 모두 같은 답(0.4 s).
  어떤 ID 를 Y 로 쓸지는 자유 → 주행 거리로 고르면 됨(도전 C 와 연결).
- 정렬: 횟수 안정 정렬(오름 = P2-01 · 03, 내림 = P2-02 · 04), 동률은 R → Y → G. Q1(RGRRGRGGYGYG, P2-01) → L1 Y2 · L2 R4 · L3 G6.
- 주사위 칸(장소 중심 기준 mm, +Y 위): 1 (0,0) / 2 (−60,60)(60,−60) / 3 = 2 + (0,0) / 4 (±60, ±60) / 5 = 4 + (0,0) / 6 x = ±60 × y = 60 · 0 · −60.
- 담당: 할당 · 정렬은 mission(판단) 쪽 코드. 이 표 형식과 규칙을 팀에 제안.

## ⑥ 바코드 다시 계산 (2026-10-28 14:0x, 사용자 실측 라벨로)

**정정(15:3x): 64.8 × 17.7 mm 는 막대 구간(첫 막대 ~ 마지막 막대 · 막대 높이) → 모듈 0.72 mm. 아래 0.589 mm · 모듈당 화소 값은 틀린 가정으로 낸 것. 실물 사진 판독 결과는 `~/git/lv2_next_module/mine/261028/인지전달_261028.md` 1-4 · 1-5.**

- 라벨 64.8 × 17.7 mm(사용자 실측, "이 값으로 진행"). Code 128 'P2-0x' = 앞뒤 빈칸 10 모듈씩 포함 110 모듈. 라벨 폭 전체에 110 모듈이 들어간다고 보면(인지 월드 가정과 같음) **모듈 0.589 mm**(예전 '20 × 35 mm' 기준 0.32 mm 의 1.8 배).
- 모듈당 화소(f 는 가정 · 실측 전, 정면): 640 × 480(f ≈ 283 px) 0.10 m 1.67 · 0.15 m 1.11 px / 1920 × 1080(f ≈ 636 px) 0.10 m 3.75 · 0.15 m 2.50 px. R3 렌더(10-25)에서 1.1 px 는 zbar 0 % → **바코드 때만 고해상도 한 장(사용자 예외)은 그대로 필요**. 1080p 로 2.5 px 이상 = 0.15 m 이내.
- 위치: 인지 월드 가정 = 벽면 x 1.5 mm, y 0.55~0.75 m, **높이 0.10~0.38 m 무작위**(발제 (80, 650, 450) 와 다름).
- 팔 도달(모의 · 기구학, `check_barcode_reach_wall.py` · `.log`, URDF 261027_1711, 벽 · 신호등 충돌 상자 가정): 벽 앞 **0.15 m · 광축 수평**이면 높이 0.10 · 0.20 · 0.30 · 0.38 m 모두 됨(차체 중심 x 0.42 · 0.32 · 0.24 · 0.30 m). 벽 앞 0.10 m 수평은 모든 높이에서 못 감(±15° 기울이면 대부분 됨). 손목 roll 이 3.14 인 해가 많아 영상이 180° 돌 수 있음(zbar 는 방향 무관).
- 남은 것: 높이가 무작위라 먼저 라벨 높이를 찾는 단계가 필요(팔 카메라 640 × 480 으로 멀리서 흰 라벨 찾기 또는 출발 자세 앞 D435) → 0.15 m 로 다가가 고해상도 한 장 → zbar. 새 월드 렌더로 판독률 시험은 기준 승인 뒤.
