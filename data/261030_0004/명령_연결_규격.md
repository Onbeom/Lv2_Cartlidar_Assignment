# Nav2와 주행 담당 사이의 개인 연결 시제품

(필수 · PC 모의 → Jetson 별도 검증) 이 문서는 팀 반영 전 검토용이며 실제 모터 실행 안내가 아니다.

| 토픽 | 형식 | 역할 |
|---|---|---|
| /navigation/goal_pose | PoseStamped, map | 미션에서 보내는 목표. 활성 목표 교체/취소 API는 아직 미구현 |
| /navigation/state | String | IDLE/WAIT_INPUT/WAIT_PATH/WAIT_REPLAN/FOLLOWING/SUCCEEDED |
| /navigation/path_valid | Bool | 조정기의 경로 유효성 heartbeat. false/0.30초 초과 무수신이면 정지 |
| /cmd_vel_nav_raw | TwistStamped | 실제 Nav2 controller 출력 |
| /navigation/observations_valid | Bool | 깊이·CameraInfo·지도·촬영시각 TF 검사 결과 |
| /perception/obstacle_stop | Bool | TFmini 정지 요청. true/0.30초 초과 무수신이면 정지 |
| /cmd_vel_nav | TwistStamped | 개인 Nav2 가지의 최종 출력. 팀 기존 mux의 nav 입력과 형식 일치 |

명령은 linear.x=m/s·angular.z=rad/s, 다른 축0, header.frame_id=base_link. 새 발행 시각 stamp를 넣는다. 개인 명령 게이트의 수신TTL은 명령0.25초·관측0.30초·경로0.30초·TFmini0.30초다. 관측의 내부 검사는 깊이/CameraInfo 수신0.30초·깊이stamp0.30초·지도수신/지도stamp0.50초·유효깊이≥5%다. 이 수치는 PC 연결 기능 시험 조건이며 실물 허용오차/제동시간이 아니다.

새 촬영 시각 TF가 늦으면 이전에 TF까지 확인한 관측이0.30초 안에 있을 때만 그 이전 관측의 유효성을 유지한다. 최신 TF를 과거 영상에 대입하지 않는다. 불확실한 공간이나 사라진 동적 지도를 임의로 자유공간으로 채우지 않는다.

**nav 명령0은 로봇 전체의 최종 정지를 보장하지 않는다.** 팀 mux에서 drive/teleop의 우선순위가 더 높다. TFmini 최종 정지는 제어 담당이 모든 모드에 적용해야 하며 `/e_stop`에 중복 발행자를 추가하지 않는다. 요청 본문은 `Cartlidar/issues/261030_Nav2_명령_제어연결.md`에 준비했다. 실제 이슈 생성·팀 파일 변경은 하지 않았다.
