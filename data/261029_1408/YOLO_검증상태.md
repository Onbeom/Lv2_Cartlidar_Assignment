# YOLO 운용 연결 검증 상태

## 완료한 개인 작업

- Ultralytics8.4.189·PyTorch2.11.0+cu128·실제YOLO11n모델 확인.
- 기존6클래스/다음4클래스 이름표를 구분해 색·모양 변환. 파랑은 차체/팔 목표 후보에서 제외.
- TensorRT코드에 고정batch·형상·float32 I/O·출력채널수 검사를 추가. 다만 PC에서는 TensorRT를 끈 빌드이므로 이 GPU코드는 아직 컴파일/실행 검증 전.
- ROS패키지 개인빌드 성공, C++110/110 통과.
- 기존ft1b 복사본의 ONNX 내보내기·checker 확인·고정실물2장 PyTorch/ONNX 동등성 통과.
- 모델/ONNX SHA256·입출력·클래스순서·버전을 models/manifest.json에 기록.
- 기존 모델 결과에서 신호등 주변 오검출도 보임. 변환 일치를 인식 정답률로 해석하지 않음.

## 이어서 필요한 검증

1. TensorRT를실제로사용할Jetson의OS/JetPack/CUDA/TensorRT를확인한다. 교안예시버전으로임의교체하지않는다.
2. 같은ONNX로대상엔진을만들고 `config/yolo_ft1b_legacy6.yaml`의6클래스순서를사용한다. 향후4클래스모델에는그에맞는표를사용한다. 채널수검사만으로잘못된동일개수이름순서를자동검출할수는없으므로manifest와함께배포한다.
3. 고정입력에서TensorRT출력과PyTorch/ONNX를비교한다. FP32기준후FP16을별도비교한다. 전처리/letterbox·NMS·클래스순서를함께대조한다.
4. 현재C++후처리는클래스전체에NMS를적용하는기존경로다. Ultralytics기본클래스별NMS와겹침장면결과를비교해수정여부를결정한다. 이번ONNX동등성시험은같은C++형후처리비교이며Ultralytics전체후처리동등성까지입증한것이아니다.
5. 새실물양성촬영묶음을확보해4클래스ft2를학습하고, 미사용실물평가에서색/모양별Precision·Recall·mAP·오검출을측정한다.
6. track_id와tag_id를별도관리하고가림·교차·재등장실물영상으로ID교체/복구를측정한다. 현재단일대상잠금의정확도를다중객체재식별정확도로대신하지않는다.

## 팀 반영

팀 코드 수정은 아직 하지 않았다. yolo_classmap.patch는R6v5개인사본기준의검토자료다. 최신팀코드와A1변경에합쳐빌드/시험한뒤사용자허가를받고fix/새브랜치에서반영해야한다. 커밋·push는사용자가직접한다. 현ft1b/ONNX는변환확인용이며최종운용모델로확정하지않았다.
