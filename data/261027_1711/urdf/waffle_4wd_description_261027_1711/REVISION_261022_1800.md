## 바꾼 것

### 1. 라이다 scan 프레임 방향

라이다 두 대는 CAD와 실물 모두 3층 판 아래에 거꾸로 매달려 있다. 그런데 scan 프레임만 바로 선 방향이었다.

| 관절 | 이전 rpy | 이후 rpy |
|---|---|---|
| `lidar_front_scan_fixed` | `0 -0 0` | `π 0 0` |
| `lidar_rear_scan_fixed` | `0 -0 π` | `π 0 π` |

- 위치와 높이는 그대로다(lidar 링크 기준 z 0.06085 m). 이 높이는 가정한 스캔 띠의 가운데이고 보정하지 않았다.
- 메시, 질량, 관성, 충돌 형상도 그대로다.
- roll π를 넣으면 앞(x)은 그대로이고, 좌우(y)와 위아래(z)가 함께 뒤집힌다. 스캔 점은 센서 평면(z = 0) 위에 있으므로 각도 θ가 −θ로 바뀐다. 즉 회전 방향이 반대가 된다.
- base_footprint 기준 결과는 다음과 같다.
  - `lidar_front_scan`: 위치 (0.1855, 0.05, 0.0676) m, z축 (0, 0, −1), x축 (1, 0, 0)
  - `lidar_rear_scan`: 위치 (−0.1855, −0.05, 0.0676) m, z축 (0, 0, −1), x축 (−1, 0, 0)

### 2. RealSense D435 렌즈 프레임 추가

`top_camera_front_optical_frame`과 `top_camera_rear_optical_frame`은 CAD의 스테레오 렌즈 원통 중점이다. 각각의 자식으로 광학 프레임 세 개를 붙였다. 축 규약은 x 오른쪽, y 아래, z 광축이다.

| 프레임 | 부모(중점) 기준 위치 [m] | 자세 rpy [rad] |
|---|---|---|
| `*_infra1_optical_frame` (왼쪽 적외선, depth 원점) | (−0.025020575, 0, 0) | 0 0 0 |
| `*_infra2_optical_frame` (오른쪽 적외선) | (+0.025020575, 0, 0) | 0 0 0 |
| `*_color_optical_frame` | (−0.040115534, 0.0000702, −0.0001825) | (−0.0064146, −0.0035145, 0.0036612) |

- 값은 D435 시리얼 `261822072247`(펌웨어 5.15.1.55)의 공장 보정값이다. `rs-enumerate-devices -c`로 2026-10-22에 읽었고, 원문은 `261022_1800/calibration/`에 있다.
  - 적외선 baseline은 0.0500412 m다.
  - color 원점은 infra1 기준으로 (−0.0150950, 0.0000702, −0.0001825) m에 있다. 출력값 Color→Depth를 그대로 썼다.
  - color 자세는 출력 행렬 Color→Depth를 행 기준으로 읽어 rpy로 바꾼 값이다. 행 기준 읽기가 맞는지는 이동 벡터 두 개로 검산했다(오차 2.1e-9 m).
- **가정**
  - 중점을 두 적외선 렌즈의 가운데로 보고, 두 렌즈를 중점에서 좌우로 baseline/2씩 둔다.
  - 두 번째 D435도 같은 보정값이라고 본다. 시리얼이 다른 기기는 공장 보정값이 조금씩 다르다.
  - 자세 차이(0.47°)는 color 프레임에만 넣었다.
- 실물에서 realsense2_camera를 쓸 때는 카메라 TF 발행을 끈다(`publish_tf:=false`). URDF가 이 프레임들을 발행하므로, 같은 TF를 두 노드가 발행하지 않게 하기 위해서다.
