# 앞 D435 장착 각 보정 (실물 R1) — 11-12

- 목적: URDF 의 앞 D435 장착 값(`top_camera_front_link`, base_link 기준 xyz −0.0481 0.0250 0.4836 · rpy 0 0.6144 0)이 실물과 얼마나 다른지 잰다. 필요하면 고친 값을 낸다.
- 근거: 상자 측정(measure_front, PR #228)의 남은 오차 몫은 보정이다. 요 1° 이면 상자 가운데가 14.7 mm 어긋나므로 요 ≤ 0.7° 가 필요하다(`261112_0600_box45/README.md` ⑩).
- 실물 시험이다. 아래 '모의' 표시가 붙은 것만 모의다.

## 방법
- 좌우 바퀴 바깥 면에 곧은 자(1 m 이상)를 하나씩 붙인다. 앞 · 뒤 바퀴가 둘 다 닿게 하고, 앞으로 내민다.
  - 자 방향 = 차체 앞 방향(바퀴 축에 수직)으로 본다.
- 보정용 tag36h11 6 장(id 20 ~ 25, 검은 사각형 100 mm, `tags_calib_36h11_id20-25_A4.pdf`. 과제 태그 ID 0 ~ 14 와 겹치지 않게 함)을 바닥에 놓는다.
  - 자 안쪽 가장자리에 흰 테두리 한 변을 붙인다.
  - 줄마다 3 장, 앞바퀴 축에서 약 30 · 55 · 80 cm(base x 약 0.40 · 0.65 · 0.90 m) 자리에 놓는다.
- Jetson 에서 앞 D435 컬러 30 장과 K · 드라이버 TF 를 저장한다(`jetson/cal_capture.py`). PC 에서 푼다(`front_cal.py solve`).
- 풀이 순서
  1. 태그마다 IPPE 자세를 구하고, URDF 값으로 base_footprint 에 옮긴다.
  2. 평면 법선을 z 로 맞추는 돌림에서 롤 · 피치 오차를 구한다.
  3. 두 줄 방향을 x 로 맞추는 돌림에서 요 오차를 구한다.
  4. 평면 z = 0 이 되게 높이를, 두 줄 가운데 = y 0(바퀴 좌우 대칭 가정)이 되게 옆 값을 맞춘다.
- 놓기 반복: 같은 자 · 태그에서 로봇을 뺐다가 다시 붙이는 일을 3 번 한다(A1 · A2 · A3). 그중 한 번은 자도 다시 붙인다.

## 바꾼 방법: 모니터 판 (11-12 사용자: 인쇄 불가 → 모니터)

- 왼쪽 바퀴 바깥 면(앞 · 뒤)에 곧은 자를 붙여 앞으로 내밀고, 화면 위쪽 테두리를 자에 붙인다(화면 오른쪽 = 로봇 앞). 화면 왼쪽 끝은 앞바퀴 축에서 약 30 cm 앞.
- 기울기: 휴대폰 수평계를 같은 방향으로 화면 위와 로봇 옆 바닥에 놓고 잰 값의 차(앞뒤 · 좌우)를 `--tilt` 로 넣는다(휴대폰 치우침이 빠진다).
