## 1. YOLO가 설치돼 있는가, 버전을 바꿀 필요가 있는가

노트북의 `/home/pa4/yolo-venv`에 설치돼 있다. 기본 PATH와 시스템 Python에는 없다. 가상환경도 이 컴퓨터에 설치한 것이며, 활성화하지 않은 터미널에서 `yolo`가 안 잡히는 것이 정상이다.

확인값: Ultralytics **8.4.189**, PyTorch **2.11.0+cu128**. 학습 모델은 **YOLO11n**(실제 yaml `yolo11n.yaml`)이다. 패키지의 8.4.189와 모델 세대 YOLOv8/YOLO11은 다른 정보다.

(필수 · PC, 설치 확인)
```bash
/home/pa4/yolo-venv/bin/yolo version
```

ROS 전체에 ‘YOLOv8 이하만 가능’이라는 제한은 없다. Isaac ROS의 특정 YOLOv8 디코더가 기대하는 텐서 형식과 사용하는 모델의 출력이 맞는지가 문제다. 모델 파일명만 바꾸어 넣으면 안 되지만, 무조건 YOLOv8로 재학습하거나 디코더를 새로 만들 이유도 없다.

현재 ft1b는 기존 6클래스 모델이며, 실제 CPU 출력은 `[1,10,8400]`. 현재 C++ TensorRT 후처리가 기대하는 `[1,4+클래스수,N]`과 기본 배열 형태가 맞는다. 그러나 기존 node는 클래스 0~2만 색으로 읽어 학습 클래스표와 의미가 맞지 않았다. 개인 새 빌드 `261029_1408`에서 명시 클래스표와 출력 채널 수 검사를 추가했다. 이전 6클래스와 다음 4클래스의 이름 순서를 구분하며, 파랑은 목표 후보에서 제외한다. 팀 반영·Jetson TensorRT 검증은 아직이다.

## 2. AprilTag와 퍽의 축

태그 자세는 태그 면 중심·가로/세로·법선 기준이고, 퍽 자세는 물체 중심·물체 축 기준이다. 태그→물체 장착 관계와 치수를 사용해 변환해야 한다. 현재 `Puck.pose`의 z축은 퍽 긴 축이며 `orientation_valid`가 참일 때만 방향을 사용한다. 번호는 읽었지만 방향이 불명확한 관측도 구분한다.

현재 `/perception/pucks`는 물체 자세를 내보내며, 원시 태그와 물체 축을 각각 독립 TF로 모두 발행하는 구성은 아니다. 태그가 여러 면에 같은 ID로 붙었다면 ID만으로 보이는 면과 모든 물체 축을 알 수 없다. 기존 코드는 보이는 면의 색 영역·기하로 중심과 긴 축을 추정한다. 대칭 물체의 관측 불가능한 회전을 임의 확정해서는 안 된다.

## 3. CenterPose와 nvblox

CenterPose는 태그 가림 중 자세를 보완하는 비교 후보다. 우리 퍽용 학습 모델·3D 라벨·ROS 연결은 아직 없다. 공개 신발 모델을 퍽에 그대로 사용할 수 없다. YOLO 상자 라벨만으로 CenterPose를 학습할 수 없으며 카메라 K·일관된 객체 좌표/3D 상자·자세/크기 관련 라벨이 필요하다. 물체가 대칭이면 회전 정답도 대칭을 고려해야 한다. CenterPose 출력만으로 영구 ID와 가림 복구가 자동 완성되지 않는다.

nvblox는 담당 대상으로 확정했다. 깊이와 촬영 시각 자세를 누적해 표면·장애물 거리장을 만들고 Nav2 비용지도에 연결한다. YOLO가 ‘무엇인가’를, 깊이 거리 지도가 ‘어디가 막혔나’를 보완한다. 먼저 고정 D435와 신뢰 가능한 odom/TF부터 연결한다. RGB 팔 카메라에 깊이가 있다고 가정하지 않는다.

PC의 nvblox ROS/nav2/rviz-plugin 5.0.0 설치를 확인했다(사용자 설치 완료 후 dpkg 확인). 이제 실제 입력 연결을 검증한다. 설치 완료는 지도 생성/성능 검증 완료와 구분한다. CenterPose도 아직 설치하지 않았다. 기존 PC·Jetson 환경을 우선하며 교안의 JetPack/설치 예시를 그대로 적용하지 않는다.

## 4. 실물 약 400장과 합성 사진

Isaac Sim 영상으로 YOLO를 학습할 수 있고 이미 학습에 사용했다. 기존 모의 학습 렌더는 60개 월드·학습 영상3600장이며, ft1b는 모의 사전학습 후 실물과 혼합한 추가 학습이다. Isaac Lab을 사진 생성 때문에 별도로 도입할 필요는 없다.

확인한 현재 실물 라벨391장 중 퍽 포함162장·빈장면229장이다. 빨강 양성은 r13/r14 두 촬영 묶음에 있어 학습·검증·평가 3분할 모두에 독립 빨강 장면을 배정할 수 없다. 분할 도구는 이 조건에서 학습 자료 생성을 거부하도록 고쳤다. 같은 장면의 인접 프레임을 나눠 넣어 해결하지 않는다.

사용자 촬영이 필요한 것은 실제 D435/팔 카메라의 색·노출·반사·가까운 거리·가림·흐림과 실물 정답 평가다. 특히 네 종류를 여러 독립 장면에서 모두 담고, 0.4~1.0m 부근의 빨강도 포함해야 한다. 추적 평가는 정지 사진 대신 가림→복구·화면 밖→복귀·같은 종류 겹침→분리의 연속 영상과 실제 ID가 필요하다.

제가 생성할 것은 모의 배치·거리·각도·광원·재질·부분 가림과 자동 상자 라벨, 이후 TF·3D 자세 정답을 가진 시퀀스다. 실제 사진을 대체했다고 하지 않고, 합성만 학습한 경우와 실물 혼합을 같은 실물 미사용 자료에서 비교한다. 사용자에게 남은 촬영·장비 단계는 한 번에 체크리스트로 전달한다.

## 5. 학습·내보내기·배포

```text
PC 사진/라벨 검사 → Ultralytics/PyTorch 학습·검증 → ONNX
Jetson ONNX→TensorRT 엔진 생성 → 추론/디코딩 → ROS 인지 메시지
```

TAO는 별도 학습 경로 선택지이며 현재 YOLO에 추가로 반드시 필요하지 않다. 엔진은 실제 대상 Jetson의 TensorRT/GPU 환경에서 생성한다. 전처리·클래스표·출력/후처리를 함께 고정하고 같은 영상의 PyTorch/ONNX/TensorRT 결과를 비교한다.

현재 확인: 기존 ft1b 복사본을 고정640·batch1·NMS없음·opset17로 ONNX 내보내기 완료. 실물 사진2장의 동일 입력 비교에서 박스 원시값 최대차0.00423px, 점수 최대차0.00000254 이하, 검출수6/6·5/5 및 클래스 일치·같은 후처리 박스 IoU1.0이었다. **변환 동등성**이며 검출 정답률은 아니다. Jetson TensorRT 비교는 아직이다. 파일/해시/입출력/버전은 `261029_1408/models/manifest.json`과 결과 폴더 `YOLO_변환_261029/summary.json`에 있다.

## 6. 추적과 영구 ID

YOLO의 track 기능에는 별도의 추적기가 연결된다. ByteTrack·BoT-SORT 등은 이동 예측과 프레임 간 검출 연결을 제공한다. 검출 클래스·학습 라벨·임시 track_id·실물 tag_id는 서로 다르다. 임시 추적 번호를 영구 퍽 번호로 취급하지 않는다.

현재 기본 코드는 odom 위치 주변에서 선택 대상 하나를 유지하고, 팔 영상에서는 같은 클래스·가까운 중심·비슷한 폭으로 박스를 유지한다. 모든 퍽의 장기 ID를 관리하는 다중 객체 추적기는 아니다. 화면 밖에서 오래 사라지거나 비슷한 퍽들이 겹쳤다 분리되면 오연결 가능성이 있어 개선이 필요하다.

개선 방향은 track_id↔tag_id를 별도 관리하고, 위치/속도·측정 시각·공분산·색/모양·관측 가능성을 함께 사용해 일대일 연결하는 것이다. 모호하면 여러 후보를 하나의 물체로 합쳐 확정하지 않고 LOST/HOLD로 보류한다. 태그 재검출로 영구 ID를 재확인한다. 외형이 같은 여러 퍽이 완전히 가려진 상태에서 서로 바뀌고 태그도 보이지 않으면, 영상만으로 원래 ID를 확정할 근거가 없다.

실물 재식별 정답률·ID 교체율은 아직 측정하지 않았다. R6 정지 배치 ID 일치율이나 단위시험 통과율을 재식별 정확도로 대신하지 않는다. confidence도 실측 정답 확률로 해석하지 않는다.

## 7. 사람·던진 장애물·정적/동적 구분

즉각적 충돌 위험은 의미 분류를 기다리지 않고 라이다/깊이 관측으로 감속·정지를 요청해야 한다. 현재 코드의 `/perception/obstacle_stop`은 TFmini 입력이다. 모든 방향의 라이다 안전 정지가 완성됐다고 볼 수 없다. 라이다/깊이→안전 요청→최종 제어기의 실제 연결을 추가 확인해야 한다.

지도 좌표에서 관측을 시간 연결해 움직임을 추정하고 정적 지도와 현재 동적 점유를 분리한다. 사람 통과 흔적을 영구 벽으로 누적하지 않으며, 던져진 물체도 이름을 몰라도 장애물로 취급한다. 움직임 판별에서는 로봇/카메라 움직임과 TF 오차를 보정해야 한다.

사람 분류는 여유 거리·대기/회피 정책을 개선하는 데 유용하지만, 방해하려는 의도를 판정할 필요는 없다. 현재 퍽 YOLO에는 사람 클래스가 없다. 별도 모델/분할이나 nvblox 동적 모드를 비교할 수 있지만 아직 통합하지 않았다. 센서 사각·프레임 사이에 갑자기 들어오는 물체의 완전 회피를 보장하지 않는다.

## 8. 작은 태그·큰 태그·바코드 대응표

기존 규칙은 작성돼 있다. 작은 tag36h11 ID0~11/16mm는 퍽 번호, 큰 ID12/13/14는 L1/L2/L3이며 48mm는 사용자 실물 인쇄 크기 확인 완료(2026-10-29). P2-01·03은 오름차순, P2-02·04는 내림차순, 동률은 R→Y→G다.

퍽 ID별 색·모양·초기 위치는 고정 정답이 아니라 실제 B0 조사로 등록한다. 현재 정보는 설정·월드 생성기·할당 시제품·조사 노드에 나뉘어 있었다. 새 통합 대응표 초안 `261029_1408/config/mission_perception_catalog.yaml`에 모았지만 **현재 mission이 이 파일을 읽도록 연결한 상태는 아니다.** 측정된 면별 고정 tag→object 장착 변환표도 완성된 상태는 아니다.
