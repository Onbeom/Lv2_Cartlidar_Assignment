## 무엇을
팔 카메라 태그 검색을 줄였습니다. 줄인 영상의 전체 2배 재검색에서 APRILTAG 를 빼고, 첫 APRILTAG 는 절반 해상도에서 사각형을 찾습니다. 앞 영상 태그 둘레만 찾는 `find_tracked` 를 추가했습니다. 둘레는 원래 크기 → 0.5 배 → 2 배로 찾고, 그래도 놓치면 그 장에서 바로 전체 검색합니다. 놓치지 않아도 15 장마다 전체 검색합니다(`marker.track_full_every`, 0 = 끔). D435 경로는 그대로입니다.

## 왜
정밀 정렬 · 집기 모드 7 에서 태그 검색이 처리 주기(66.7 ms)보다 길어 태그 없는 장면이 4.1 Hz, 결과 나이 300 ms 초과 65.4 % 였습니다. 태그 없는 장면 시간의 67 % 가 전체 2배 APRILTAG 였습니다.

## 시험
- PC(OpenCV 4.6): perception gtest 202 개 실패 0(고친 뒤 다시 셈), 추적 · 줄인 검색 시험 7 개 추가.
- Jetson 카메라 3 대 · 관절 흉내 50 Hz · 모드 7: 태그 없는 장면 4.1 → 14.5 Hz, 나이 p99 389 → 231 ms, 300 ms 초과 65.4 → 0.0 %. 태그 사진 6.7 → 12.3 Hz, p99 310 → 247 ms.
- Jetson 실물 클립 재생: 정답 ID 잃음 0, 꼭짓점 차이 p99 0.28 px(기존 대 새 전체 검색).
- 실물 팔 J1 왕복(0.1 · 0.25 · 0.5 rad/s) 녹화 9 판 재생: 처음 판은 둘레를 원래 크기로만 찾아 0.5 rad/s 등속 구간 17~37 % 를 잃었습니다. 둘레를 0.5 배 · 2 배로도 찾고 그래도 놓치면 그 장에서 전체 검색하도록 고친 뒤 9 판 모두 잃음 0, 결과 간격 최대 165 ms.

## 한계
- 인지 + 카메라 CPU 평균 51.5~53.4 % 로 이번 기준 45 % 를 넘습니다(수정 전 47.3~50.0 %, 인지 노드 자체는 줄었습니다). 팔 입력은 30 Hz 로 두고, 전체 구성 부하는 실물 전체 측정에서 확인합니다.
- 약 30 cm 흉내 영상에서 550 장 중 2 장을 잃습니다. 원래 기준 '잃음 0' 에는 불통과입니다.
- 300~400 px 로 크게 보이는 태그는 추적이 전체 검색보다 느립니다(평균 111 ms). 놓친 장은 전체 검색이 끼어 그 장 처리가 p99 153 ms 까지 늘어납니다.
- 왕복 녹화는 태그 약 96 px 한 장, 0.5 rad/s 등속 표본 28~35 장입니다. 고친 뒤 실시간 Hz · CPU 는 다시 재지 않았습니다.
