## 2. footprint 위치 표시 분석 (pxr로 관절 프레임·질량 중심 위치 계산)

```shell
~/isaacsim-venv/bin/python -I - <<'EOF'
from pxr import Usd, UsdGeom, UsdPhysics, Gf
s = Usd.Stage.Open('sim/isaac/usd/waffle_4wd_r1/waffle_4wd/waffle_4wd.usda')
r = s.GetDefaultPrim()
with Usd.EditContext(s, s.GetSessionLayer()):          # 파일은 바꾸지 않고 세션에서만 variant 선택
    r.GetVariantSets().GetVariantSet('Physics').SetVariantSelection('physx')
c = UsdGeom.XformCache()
for p in Usd.PrimRange(r):
    if p.IsA(UsdPhysics.Joint):                        # 관절 프레임 = body0 좌표의 localPos0
        b0 = p.GetRelationship('physics:body0').GetTargets()[0]
        pos = c.GetLocalToWorldTransform(s.GetPrimAtPath(b0)).Transform(Gf.Vec3d(p.GetAttribute('physics:localPos0').Get()))
        print(p.GetName(), pos)
EOF
```

- 결과: `lidar_front_fixed`, `lidar_rear_fixed` 두 관절이 모두 (0, 0, 0.0067 m) = base_link 원점에 있다. URDF에서 이 관절 원점이 `0 0 0`이고, 라이다 실제 위치(±0.1855 m)는 그 아래 `lidar_*_scan_fixed`에 있다. 고정 관절이라 물리 영향 없음 → 문제없음.
- 질량 중심 14개 중 footprint 근처에 있는 것은 없음(라이다 CoM은 (±0.175, ±0.049, 0.084 m)). 화면의 질량 표시는 라이다 링크 원점일 가능성이 크고, 질량 값 자체는 URDF와 일치(2단계 ④).

## 4. 단위·축 확인 (mm인 줄 알았던 것)

```shell
grep -o 'scale="[^"]*"' mine/urdf/waffle_4wd_description_261021/urdf/waffle_4wd.urdf | sort | uniq -c
# → 504 scale="1 1 1"
grep -ho '<unit[^>]*>' mine/urdf/waffle_4wd_description_261021/meshes/main/*.dae | sort | uniq -c
# → 14 <unit name="meter" meter="1.0"/>   (up_axis Z_UP)
```

- CAD(Fusion)는 mm로 작업하지만 내보낸 URDF는 이미 m. STL 꼭짓점 값도 m 범위(예: −0.0921~0.29), USD metersPerUnit 1. 변환한 것 없음, 변환 필요 없음.
- 메시 배율 0.001은 메시 파일 숫자가 mm일 때만 필요. 여기서는 1이 맞다.
- 축: ROS REP-103(x 앞·y 왼쪽·z 위) 그대로. 앞 라이다·팔 +x, Front_Left 바퀴 y = +0.1396 m, 바퀴 중심 z = 0.033 m. 변환이 필요한 곳은 4단계의 Isaac 카메라(USD 카메라는 −Z가 시선)와 관절 각도 단위(USD degree ↔ ROS rad).

| 질문 | 답 |
|---|---|
| 차체+바퀴 크기 | 0.371 × 0.305 × 0.513 m (가로·세로 600 mm 이내) |
| 라이다 포함 길이 | 0.4445 m |
| 관절 0 자세(팔을 앞으로 편 상태) 전체 길이 | 0.652 m (팔 접은 기준 600 mm라 문제없음) |
