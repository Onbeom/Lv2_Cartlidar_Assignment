# 가상 과제 월드 (인지 파트 시험용)

과제 공개 전에 인지 코드를 시험하려고 만든 Isaac Sim 6.1용 USD 월드다. **과제 조건은 대부분 가정**이며 공개되면 바꾼다. 팀 저장소에는 넣지 않는다(학습 폴더 `Cartlidar/`).

## 구성

| 항목 | 내용 | 근거 |
|---|---|---|
| 미로 | Twin Closed Maze 위쪽 반 + 가운데 공용 벽(가운데 벽 y = 0, 바깥 벽 y = 3.152 m). 720 판 17 + 380 판 20 + 공용 6, 기둥 45개 | 기둥 위치 SDF, 벽 위치 STL, 방향은 **도면**(`photos/기본맵사진.jpg`). 도면은 SDF/STL을 y로 뒤집은 모양이라 뒤집어서 씀(사용자 결정 2026-10-23) |
| 벽판 | 높이 0.380, 두께 0.003 m, 남회색 광택 | 실측(사용자). 아래 틈 0은 가정, 반투명은 넣지 않음 |
| 기둥 | 몸통 0.0355 m 각, 머리 지름 0.060 m, 꼭대기 0.400 m. 벽 끝·모서리·갈림 기둥 = AL(은색), 나머지 = 출력 연결부(파랑), 머리는 모두 파랑 | 실측 + 도면 범례(AL 30곳, 규칙으로 센 수와 같음). 머리 두께 0.020 m는 가정 |
| 바닥 | 회색 카펫, 마찰 0.8/0.6 | 마찰은 시뮬레이션 연습 세션 시험 조건(가정, 실측 대기) |
| 선반 | 0.20 × 0.20 × 0.08 m 회색 상자 3개, 무작위 칸의 벽 옆(틈 0.02 m) | 높이만 사실, 나머지 가정(설계 문서 5절) |
| 퍽 | 12개 모두 선반 위, 선반마다 4개. 직육면체 30×30×60 mm, 원기둥 지름 30·높이 60 mm. 빨강·초록·파랑 각 4개, **색마다 원기둥 1~3개(가정)**. 서 있음/누움 반반(가정), 방향 무작위. 질량 0.030/0.024 kg(가정) | 크기·색·개수는 사실(사용자) |
| 퍽 태그 | tag36h11 번호 0~11, 퍽마다 같은 번호 6면. 검은 테두리 바깥 0.018 m(가정). **원기둥은 옆면 4곳(휘어진 스티커) + 위·아래(가정)** | 0.024 m는 원기둥 윗면(내접 정사각형 21.2 mm)·옆 둘레(94.2 mm)에 안 들어가서 줄임 |
| 과제 마커 | DICT_4X4_50, 과제 A·B·C = 10·11·12, 한 변 0.10 m, 중심 높이 0.15 m, 출발 칸(c00) 벽판 중 무작위 하나에 칸 안쪽을 향함 | 모두 가정 |
| 출발 칸 | **왼쪽 아래 구석 칸 c00**(x −2.202 ~ −1.468, y 0 ~ 0.788 m: 왼쪽 바깥 벽·가운데 벽·긴 줄 벽 사이, 오른쪽만 열림)의 가운데. 흰 테이프 바깥 0.60 m, 폭 0.03 m. 같은 곳에서 출발하고 돌아옴. **출발 때 팔이 테이프를 넘는 것은 상관없음**(판정하지 않음), 도착해 멈춘 뒤에만 테이프를 넘지 않고 벽에 닿지 않으면 됨(사용자 2026-10-23, 도착 판정은 아직 없음) | 칸·가운데 위치는 사용자 지정(2026-10-23), 테이프 크기·색은 가정 |
| 로봇 | `261022_2119` USD 참조(Physics `physx`), 출발 칸 가운데 ±0.02 m(가정), 방향·팔 5관절·집게 무작위(관절 한계 안). 자기충돌·바닥 닿음·월드 겹침이 있으면 다시 뽑음. 팔·집게·바퀴 drive 이득은 시뮬레이션 연습 세션 v8 조건 | 팔 자세는 `PhysicsJointStateAPI` 위치·drive 목표로 씀 |
| 조명 | `dark`(낮·전등 끔) / `bright`(낮·전등 켬) 두 시작값 | **사진과 화면으로 맞추지 않음**(사용자 확인 필요) |

## 실행 (PC)

배치 데이터·질감 다시 만들기(한 번만, 결과는 `data/`, `textures/`에 있음):
```bash
~/isaacsim-venv/bin/python -I make_maze_layout.py
```
```bash
~/isaacsim-venv/bin/python -I make_markers.py
```
월드 만들기(결과 `worlds/seed_<n>/task_world.usda`, `layout.json`):
```bash
~/isaacsim-venv/bin/python -I build_task_world.py --seed 1 --task A --light dark
```
판정(결과 `results/check_<YYMMDD_HHMM>/`):
```bash
~/isaacsim-venv/bin/python -I check_task_world.py --seeds 1 2 3
```

## 결과 (2026-10-23, 모의·USD 정적 검사)

`results/check_261023_1112/` — **W1~W6 모두 성공**(seed 1·2·3, 출발 칸 c00 고정).
- W2: 미로 충돌체 133개(판 43 + 기둥 45 × 몸통·머리), 가장 낮은 y = −0.030 m(가운데 줄 기둥 머리 반지름).
- W3: |dz| 최대 0.0 mm(배치를 계산으로 정하므로 당연한 값. 판정은 만든 결과가 의도대로 USD에 들어갔는지 확인).
- W4: 가장 가까운 거리(L∞) seed 1 26.2 mm(arm_link_5–벽판), seed 2 95.2 mm(오른쪽 집게–벽판), seed 3 26.9 mm(arm_link_5–기둥 머리).
- W6: 출발 칸 c00, 테이프 중심 오차 0.0 mm, 마커 0.100 m·중심 0.150 m.
- 위에서 본 그림: `seed_<n>_top.png`. 주황 선 = 출발 때 로봇 윤곽(차체·바퀴·라이다·팔의 충돌 형상을 위에서 본 바깥 테두리).

이전 결과 `results/check_261023_1107/`은 출발 칸을 무작위 칸으로 둔 판(그때도 W1~W6 성공)이고, 사용자가 출발 칸을 지정해 다시 만들었다.

개발 중 시험 실행(scratchpad, 공식 결과 아님)에서 W3이 누운 원기둥 3개에서 실패했다. 판정 코드가 원기둥을 사각 범위(BBoxCache)로 감싸 아랫면을 최대 6 mm 낮게 잡은 것이 원인이어서, 판정 코드가 원기둥 축으로 정확한 범위를 계산하게 고친 뒤 공식 실행했다(배치 코드는 바꾸지 않음).

## 확인하지 않은 것·한계

- Isaac Sim에서 열어 보거나 물리를 돌려 보지 않았다(판정은 USD 정적 검사). 특히 팔 시작 자세(`state:angular:physics:position`)가 재생 시작 때 적용되는지, 누운 원기둥이 굴러가지 않는지는 미확인. 재생 전 화면에서는 팔이 관절 0 자세로 보인다.
- W4는 월드를 만들 때 쓴 것과 같은 충돌 계산 코드(`robot_geom.py`)를 쓴다(로봇 자세는 USD에서 다시 읽음). 이 코드는 MoveIt 충돌 확인 결과와 같은 쌍을 냄: 관절 0 자세 0쌍, 접은 자세 [0, 1.4992, −1.3998, 1.7, 0] 0쌍, [0, 1.5, 1.5, 1.7, 0] 3쌍(base_link–arm_link_3·4, lidar_rear–gripper_right_link).
- 센서 토픽 발행은 없다(Lyrical 브리지 검증 뒤).
- 조명 값, 벽판 색·광택, 카펫 색은 사진과 맞추지 않은 시작값이다.
- Isaac Sim에서 Colliders 표시를 All로 켜면 GPU 크래시가 난 적이 있다(STATUS 참고). 열 때 Colliders는 None으로 둔다.
