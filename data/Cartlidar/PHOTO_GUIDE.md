# 실물 RGB-D 촬영

저장 위치: `/home/pa4/git/lv2_next_module/cartlidar/photo` (소문자 cartlidar).
기존 `Cartlidar/photos`와 `photo` 폴더는 변경하지 않는다.

## 실행

```bash
cd /home/pa4/git/lv2_next_module/cartlidar
bash run_capture.sh --list
bash run_capture.sh --label pucks_bright_050cm
```

RealSense 2대를 USB 3로 연결하고 RealSense Viewer와 ROS 카메라 드라이버를 종료한 뒤 실행한다.
화면을 클릭해 키보드 포커스를 준 후 **영문 s**: 두 카메라의 현재 RGB-D 저장, **q / Esc**: 종료.
처음 2초는 노출 안정화를 기다린다. 설정은 640×480, 30 fps, 자동 노출·화이트밸런스는 장치 설정을 유지한다.
미리보기의 이름·문구·깊이 색상표는 원본 RGB에 저장되지 않는다.

앞뒤를 명확히 기록하려면:

```bash
bash run_capture.sh --front 앞카메라시리얼 --rear 뒤카메라시리얼 --label pucks_bright_050cm
```

시리얼을 지정하지 않으면 작은 시리얼부터 cam1/cam2로 저장하며 앞뒤라고 추정하지 않는다.
한 대만 촬영할 때는 `--allow-one`. 필요하면 `--width 1280 --height 720 --fps 15`로 변경한다(장치가 지원해야 함).
장착 위치·각도·카메라 설정을 실제 운용과 맞추는 것이 우선이다.

## 무엇을 찍을지

아래 수량은 첫 수집 목표이며 정확도를 보장하는 기준은 아니다. 같은 자리에서 연속 저장하기보다 물체·거리·시점을 바꾼다.

| 대상 | 찍을 장면 | 첫 목표(카메라별 RGB 기준) |
|---|---|---|
| 퍽 4종 | 빨강 원기둥/직육면체, 초록 원기둥/직육면체. 하나씩, 서 있음/누워 있음, 윗면/옆면, 태그 보임/안 보임 | 종류당 40~60장 |
| 여러 퍽 | 같은 색 밀집, 다른 색 혼합, 서로 접촉, 일부 가림, 선반·바닥, 집게 접근 전 시점 | 100~150장 |
| 방해물/빈 배경 | 파란 기둥·받침, 빨강/초록 물체, 그림자, 반사, 빈 선반·벽·바닥. 실제로 퍽이 없는 장면도 포함 | 50~100장 |
| 태그·바코드 | 실제 출력한 퍽 태그·장소 태그, P2-01~04. 정면·비스듬함, 반사·부분 가림, 실제 부착 상태. 정답 ID/문자열은 장면 기록에 남김 | 조건을 바꾸어 50~100장 |
| 신호등 | 꺼짐/빨강/노랑/초록, 약한 빛/밝은 빛, 반사·다른 유색 물체 포함, 팔 가림 | 상태당 20~30장 |
| 주사위 배치 | 맞는 눈 1~6, 누락/추가/위치 틀림/색 틀림/노랑에 형태 혼합 | 가능한 배치별 5~10장 |

- 퍽 거리 예시: 0.3/0.5/0.8/1.0/1.5 m. 2 m도 실제 관측 거리라면 포함하되 30 mm 폭은 작게 보인다.
- 각도 예시: 정면/좌우 약 30°/60°, 실제 카메라 높이·기울기를 유지한 장면. 두 카메라가 서로 반대쪽을 본다면 같은 물체가 둘 다 보일 필요는 없다.
- 조명: 밝음/보통/어두움, 그림자·역광. RGB가 맞아도 깊이가 비는 장면도 버리지 말고 기록한다.
- 태그/바코드는 가깝게 찍은 선명한 기준 사진과 실제 운용 거리의 사진을 모두 남긴다. 전체 화면에서 글자가 작다는 이유로 디지털 확대해서 원본을 덮어쓰지 않는다.
- 실제 장착 카메라가 보지 못하는 퍽 윗면·바코드는 두 RealSense 데이터만으로 해결할 수 없으므로 팔 카메라에서도 별도로 수집해야 한다.
- 장면 묶음마다 label에 대상·조명·대략 거리를 쓰면 나중에 구분하기 쉽다. 실제 정답과 실측 거리는 별도 메모한다.

**신호등의 12회 점등 횟수·시간 검증에는 연속 영상이 필요하다.** 이 도구의 s는 정지 사진만 저장하므로 켜짐·꺼짐 분류 자료만 얻는다. 이 사진들로 전체 점멸 시퀀스를 복원할 수는 없다.

## 저장 내용

각 s 입력마다 날짜·시간 폴더가 생성되고 카메라별 하위 폴더에 다음을 저장한다.

- `color.png`: 손대지 않은 컬러 이미지, YOLO 라벨링 대상.
- `depth_raw.png`: 원래 깊이 센서 격자의 uint16 깊이.
- `depth_aligned.png`: 컬러 격자에 맞춘 uint16 깊이. 값 × metadata의 depth_unit_m = 미터. 0은 유효 깊이 없음.
- `metadata.json`: 시리얼, 카메라 내부 파라미터, 깊이→컬러 외부 파라미터, 깊이 단위, 프레임 번호·시각, 수신 시 센서 설정.
- 상위 `capture.json`: 한국 시각, label, 두 프레임 수신 시각 차이.

두 카메라의 최신 프레임을 한 번에 저장하지만 하드웨어 동기화는 하지 않는다. 빠르게 움직이는 물체의 정확한 동시 촬영 자료로 취급하지 않는다.
프로그램은 YOLO 박스 정답을 자동 생성하지 않는다. 라벨링은 별도이며, 학습·검증·시험 분할은 같은 촬영 묶음이 서로 섞이지 않게 한다.

## 의존성

전용 `.capture-venv`는 시스템의 OpenCV·NumPy를 사용하고 pyrealsense2를 별도 설치한다.
다른 컴퓨터로 옮길 경우:

```bash
python3 -m venv --system-site-packages .capture-venv
uv pip install --python .capture-venv/bin/python pyrealsense2
```

컬러에 깊이를 정렬하고 시리얼로 장치를 선택하는 API는 RealSense 공식 예제를 따른다:
https://github.com/realsenseai/librealsense/blob/master/wrappers/python/examples/align-depth2color.py
https://realsenseai.github.io/librealsense/python_docs/_generated/pyrealsense2.config.html
