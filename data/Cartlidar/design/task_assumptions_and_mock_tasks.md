## 2. 사진에서 본 인지 쪽 위험

1. **파란 기둥이 파란 퍽과 색이 비슷하다.** HSV 색만 쓰면 기둥을 퍽으로 볼 수 있다. 다음 세 가지로 거른다: 깊이로 잰 실제 크기(기둥은 높이 약 0.35 m, 퍽은 60 mm 이하), 선반 높이(퍽은 바닥에서 80 mm 위), 퍽의 AprilTag. 가장 확실한 것은 AprilTag다.
2. **벽판이 거울처럼 반사한다.**
   - D435 깊이: 적외선 패턴이 광택면에서 흩어져 벽 깊이에 구멍이나 튀는 값이 생길 수 있다.
   - LDS-03: 비스듬한 각도에서 반사가 돌아오지 않아 벽이 빠져 보일 수 있다.
   - 벽에 닿으면 0점이므로, 라이다에서 벽이 빠지는 각도가 있는지 실물에서 먼저 재야 한다(시험 항목).
3. **시연은 어둡다.**
   - 컬러 노출과 HSV 범위는 어두운 조건에서 다시 맞춰야 한다.
   - D435 적외선 발광기는 어두워도 깊이를 돕는다.
   - Arducam(팔 끝)은 퍽에 가까이 붙어 그림자가 질 수 있다.
4. **AprilTag가 작다.** 30 mm 면에 붙는 태그는 한 변이 30 mm보다 작다. 상단 D435(높이 약 0.49 m, 아래로 35°)로 몇 m 거리까지 읽히는지는 태그 크기에 달려 있어서 공개 뒤에 잰다. 그 전에는 색·모양으로 찾고, 가까이 가서 Arducam으로 번호를 읽는 2단계를 기본으로 한다.
5. **보관함에 넣은 퍽이 뒤 카메라에 보일 수 있다.** 보관함 영역은 검출에서 뺀다. 이 영역은 코드 상수가 아니라 설정 파일의 상자 목록으로 둔다.

## 3. 보관함이 바뀌면 인지 코드도 바뀌나

- **바뀌지 않게 만든다.** 인지가 보관함과 관련된 것은 "보관함 안 퍽을 새 목표로 고르지 않기" 하나다. 이 영역을 설정 파일의 상자 목록(`base_link` 기준)으로 두면, 3칸에서 12칸으로 바뀌어도 설정 값만 바꾸면 된다.
- 어느 칸에 몇 번 퍽이 있는지 기억하는 것은 미션(제어) 몫이다. 인지는 집을 퍽과 꺼낼 퍽의 번호·색·모양·자세를 알려 준다.
- 보관함 안 퍽의 번호를 카메라로 다시 확인할지는 나중에 정한다. 그때는 설정에 보관함 칸 위치만 더하면 된다.

## 4. 인지 출력 메시지 초안 (팀과 상의 필요)

지금 `PerceptionResult`는 물체 하나의 위치만 있다. 필요한 것은 "보이는 퍽 여러 개 × (번호, 색, 모양, 자세)"다.

```
# Puck.msg
int32 tag_id            # AprilTag 번호 0~11, 읽지 못했으면 -1
uint8 COLOR_UNKNOWN=0
uint8 COLOR_RED=1
uint8 COLOR_GREEN=2
uint8 COLOR_BLUE=3
uint8 color
uint8 SHAPE_UNKNOWN=0
uint8 SHAPE_CYLINDER=1
uint8 SHAPE_CUBOID=2
uint8 shape
geometry_msgs/Pose pose # base_link 기준 퍽 중심. 자세는 퍽 긴 축 방향(태그로 알면 태그 기준, 아니면 깊이 점으로 추정)
bool orientation_valid  # 자세를 믿을 수 있는지
bool standing           # 긴 축이 위로 서 있는지
float32 confidence
uint8 camera            # 0 앞 D435 · 1 뒤 D435 · 2 Arducam

# PuckArray.msg
std_msgs/Header header  # stamp = 촬영 시각, frame_id = base_link
Puck[] pucks            # 가까운 것부터 정렬
int32 target_index      # 지금 고른 목표(가까운 것부터, 보관함·그리퍼 영역 제외), 없으면 -1
```

Aruco 과제 마커 결과는 별도 메시지로 둔다(`TaskMarker`: 마커 id, 자세, 해석한 과제). 마커 의미가 공개되면 정한다.

## 5. 가상 과제 (공개 전 시뮬레이션 시험용, 모두 가정)

공통 가정: Aruco 사전 `DICT_4X4_50`, 마커 한 변 0.10 m, 벽면 높이 0.10~0.20 m에 붙임. 퍽 AprilTag `tag36h11`, 한 변 0.018 m(2026-10-23 0.024에서 바꿈: 원기둥 윗면·옆 둘레에 들어가게). 선반은 0.20 × 0.20 × 0.08 m 회색 상자, 미로 안에 3개. 출발 칸은 흰 테이프 폭 0.03 m로 0.60 × 0.60 m(로봇 0.445 × 0.306 m가 들어가고 사방 여유 약 0.08 m 이상).

| 과제 | 마커가 알려 주는 것 (가정) | 맵 구성 (가정) | 인지에 요구되는 것 |
|---|---|---|---|
| A. 색 모으기 | 마커 id 10: "빨강 4개를 선반 S1에" | 선반 3개에 퍽 12개를 4개씩 무작위 자세로. 정적 상자 장애물 2개 | 색 구분, 가까운 것부터 고르기, 선반 위 높이 거르기 |
| B. 번호 순 피라미드 | 마커 id 11: "번호 0~5로 3-2-1 피라미드, 0이 아래 왼쪽" | 퍽 12개 흩어 놓기, 동적 장애물(굴러가는 공 1개) | 퍽 번호(AprilTag), 선반·쌓인 퍽 높이, 비상 정지 |
| C. 스도쿠 칸 채우기 | 마커 id 12: "2×2 칸에 번호 1·2·3·4를 행·열 중복 없이" | 칸이 그려진 판 1개, 사람 다리 모양 원기둥이 지나감 | 번호, 판 칸 위치(Aruco 4개로 판 자세), 비상 정지 |

- 세 과제 모두 출발 칸(왼쪽 아래 구석 칸 가운데)에서 방향·팔 자세를 무작위로 두고, 끝나면 같은 칸으로 돌아와 테이프 안에 멈춘다(출발 때 테이프 넘음은 상관없음).
- 시뮬레이션 월드는 시뮬레이션 담당 세션이 만든다. 인지 쪽은 각 과제의 판정(퍽 번호·색·모양·위치 오차)을 모의 시험처럼 수치로 정한다.
