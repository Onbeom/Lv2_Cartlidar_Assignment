# 신호등 영상·깊이 연속 촬영

기존 사진 프로그램은 그대로 유지한다. 아래 두 프로그램은 한 번에 카메라 한 대를 사용한다.
기존 사진 창/RealSense Viewer/ROS 카메라 드라이버를 종료한 다음 실행한다.
한 대가 연결되어 있으면 자동 선택한다. 두 대가 연결되어 있으면 `--serial`로 원하는 시리얼을 지정한다.
기존 `--allow-one` 옵션도 받아들이지만, 이 프로그램들은 기본이 한 대 촬영이다.

## 신호등 영상

```bash
bash /home/pa4/git/lv2_next_module/cartlidar/run_signal_video.sh --label signal_wall1_0.8m_lighton
```

- 미리보기 창 클릭 → **영문 s**: 120초 기록 시작. 자동으로 종료한 뒤 다시 대기한다.
- 기록 중 **s**: 일찍 정지. **q/Esc**: 저장을 마무리하고 프로그램 종료.
- 다시 s를 누르면 별도의 날짜·시간 폴더에 새 영상을 기록한다.
- 120초는 기본 길이일 뿐 12회 묶음 수를 자동 인식하지 않는다. 같은 순서가 반복되는 경우 시작 전 꺼짐부터 묶음 간 간격까지 포함해 3~4묶음을 확보한다. 부족하면 시간을 늘린다.

```bash
bash /home/pa4/git/lv2_next_module/cartlidar/run_signal_video.sh --seconds 180 --serial 261822072247 --label signal_wall2_1.0m_lightoff
```

저장: `/home/pa4/git/lv2_next_module/cartlidar/video/날짜_시간/`

- `color.avi`: 재생용 컬러 동영상(MJPEG, 설정 FPS). 미리보기 문구는 저장하지 않는다.
- `color/000000.png ...`: 손실 없는 컬러 원본 프레임.
- `depth_raw/`, `depth_aligned/`: 같은 프레임 묶음의 원시 깊이와 컬러에 정렬한 깊이 PNG(uint16).
- `frames.csv`: 실제 컬러·깊이 촬영 시각, timestamp domain, 프레임 번호, 지원하는 경우 실제 노출값.
- `capture.json`: label, 카메라 보정, 깊이 단위, 시작 센서 설정, 종료 이유, 프레임 누락·저장 결과.

동영상은 고정 FPS 재생용이다. 점멸 길이/횟수 분석에는 PNG와 `frames.csv`의 실제 시각을 사용한다.
RealSense 원본 `.bag` 파일이나 ROS 2 rosbag 형식은 아니다. 원본 RGB-D PNG와 시각 로그로 저장한다.
기록 시간에 따라 수 GB의 공간이 필요할 수 있다. 디스크가 느려 쓰기 대기열이 가득 차면 조용히 프레임을 버리지 않고 오류로 정지한다.

## 깊이 잡음용 연속 촬영 (2026-10-27 수정)

```bash
bash /home/pa4/git/lv2_next_module/cartlidar/run_depth_sequence.sh --label depth_wall_0.5m_lighton
```

미리보기에서 구도와 거리를 맞추고 **카메라와 대상을 고정**한다. 시작 후 약 2초의 준비 시간이 지난 뒤 s를 누르면 **중단 없이 계속 저장**한다. 다시 s를 누르면 해당 묶음을 마무리하며, q/Esc는 저장을 마무리하고 프로그램을 종료한다.

이전 버전의 90프레임 기본값은 약 3초 뒤 정상적으로 자동 종료했다. 현재 기본값은 `--frames 0`(무제한)이다. 정해진 개수만 필요하면 `--frames 90` 또는 아래처럼 `--frames 300`으로 선택한다. 기본값 변경은 깊이 촬영에만 해당하며 신호등 영상은 기존 120초 자동 종료를 유지한다.

```bash
bash /home/pa4/git/lv2_next_module/cartlidar/run_depth_sequence.sh --frames 300 --label depth_shelf_oblique_lighton
```

저장: `/home/pa4/git/lv2_next_module/cartlidar/depth_sequence/날짜_시간/`
영상 AVI를 제외하고 위와 같은 PNG·보정·시각 파일이 저장된다. 90장으로 5장 평균을 여러 묶음 비교할 수 있다.
시간 필터나 5장 평균은 수집 단계에서 적용하지 않는다. 분석할 때 적용한다.

`capture.json`의 `complete=true`는 목표 시간/개수와 디스크 저장 완료를 뜻한다. 무제한 깊이 촬영은 사용자가 종료했고 수집한 프레임이 모두 저장된 경우 true이다.
연속성을 평가할 때는 **`consecutive_frames=true`, `color_frame_gaps=0`, `depth_frame_gaps=0`도 확인**한다.
프레임이 누락됐더라도 파일을 남기고 누락 수를 기록하므로, 누락을 가린 채 연속 90장으로 취급하지 않는다.
같은 RGB 또는 깊이 프레임이 재사용된 묶음은 오류로 중단하지 않고 건너뛴다. `skipped_duplicate_pairs`, `reused_color_frames`, `reused_depth_frames`에 횟수를 기록한다. 실제 프레임 번호가 역행할 때는 카메라 리셋 등의 가능성이 있어 별도로 중단한다. 실제 USB/디스크 오류까지 무시하는 것은 아니다.
수집 중 손으로 카메라·선반을 만지거나 물체를 움직이지 않는다. 카메라 고정 여부는 프로그램이 자동 검증하지 않는다.

## 노출·촬영 조건

기본 RGB 설정은 복원한 **자동 노출 켬, gain 64, 자동 화이트밸런스 켬**이다.
깊이 센서의 노출·emitter 설정은 변경하지 않고 기록 시작 시 값을 저장한다.
실제 조명을 끄는 것과 RGB 노출을 낮추는 것은 다르다. 두 조건을 label로 구분한다.
수동 RGB 노출은 기존 사진 도구와 같은 `--rgb-exposure`, `--rgb-gain`, `--rgb-white-balance`로 선택한다.
퍽이 안 보일 정도의 저노출 자료를 퍽 학습의 주력 자료로 사용하지 않는다.

## 수정된 추가 촬영 목록

- 빨간 퍽만, 빨강+초록 혼합: 원기둥/직육면체, 서 있음/누워 있음, 일부 가림, 선반/바닥.
- 신호등만: 모서리/벽 한 면은 이미 수집했으므로 벽 없는 배경을 보완. 같은 자리의 유사 사진만 늘리지 않는다.
- 바코드: 실제 P2-01~04를 벽/선반에 부착, 거리·시점 변경. 최종 판독에 쓸 팔 카메라 자료도 별도로 필요하다.
- 태그: 실제 ID별 가까운 기준 사진과 운용 거리·각도 사진. 퍽 태그와 장소 태그를 구분한다.
- 카메라·대상 고정 후 벽 0.5/1.0m, 비스듬한 선반의 깊이 연속 촬영.
- 신호등 점멸 연속 영상.
- 신호등/퍽이 없는 배경, 퍽만 있는 배경도 확보한다. 벽 반사광은 실제 신호등으로 라벨링하지 않는다.
- 위 대상의 실제 조명 on/off 조건을 보완한다. 사진 수만으로 학습 충분성을 보장할 수 없으며 별도 장면의 평가가 필요하다.

**밝은 환경에서 모든 등이 꺼진 신호등 사진은 이미 있다.** 예: `photo/20261026_172316_393578/`,
`photo/20261026_172439_119242/`, `photo/20261026_172627_440580/`.
같은 조건의 꺼짐 장면을 다시 찍는 것은 필수가 아니다. 실제 조명을 끈 조건은 별도로 보완한다.
퍽은 빨강·초록 × 원기둥·직육면체의 4종이며 노란 퍽 촬영은 필요하지 않다.
