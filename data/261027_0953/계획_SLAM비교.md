# cuVSLAM ↔ Cartographer 비교 계획 (초안, 2026-10-27, 승인 전, 모의 시험)

목적: 같은 장면·같은 주행·같은 입력에서 두 방식의 위치 추정 정확도, 지도, 계산 부담, 실패 조건을 비교해 차이점과 장단점을 정리한다.

## 1. 확인한 것 (읽기만 함)

- Isaac ROS 5.0 apt 설치됨(PC): `ros-lyrical-isaac-ros-cuvslam` 5.0.0(노드·launch `isaac_ros_visual_slam_isaac_sim.launch.py` 등 포함), 인터페이스. Docker 없이 실행 가능할 것으로 보임(실행은 아직 안 함). Isaac ROS 5.0 문서는 Isaac Sim 6.0으로 검증했다고 적음(6.1 조합은 문서에 없음).
- Cartographer: `~/git/ros_test/waffle-lyrical-slam/install/`에 Lyrical 소스 빌드가 있음(2026-10-14~15 비교 실험에 씀, 최선 설정 c6 = 해상도 0.025 m · 10/40 · 회전 1°, 루프 폐합 주기 90). 지도 평가 도구 `experiments/cartographer_ab/evaluate_maps.py`(유령 벽 비율, 벽 위치 오차, 벽 채움률).
- 장면: 인지 시험용 과제 미로 월드 `Cartlidar/sim_world/worlds/b_dice/seed_*`(Isaac 6.1 USD, 벽판 높이 0.38 m · 흰 판, 기둥, 선반, 조명 0~1). 로봇·브리지는 4단계 L2 방식 (a)(`261025_0307/l2/`)를 그대로 쓴다.
- 수신 버퍼: 2026-10-27 영구 설정 끝(rmem_max 64 MB + CycloneDDS 16 MB).
- GPU 8 GB: Isaac Sim과 cuVSLAM을 동시에 돌리면 메모리가 모자랄 수 있다(실측 전).

## 2. 방법

1. **기록**: Isaac 미로에서 정해진 명령 순서로 주행하며 rosbag을 남긴다. 토픽: `/clock`, 라이다 2개 `/scan_front`·`/scan_rear`, `/odom`(바퀴), `/tf`·`/tf_static`, RealSense 앞 적외선 좌·우 영상 + CameraInfo(새로 추가, D435 공장 baseline 0.0500 m), 정답 자세(Isaac에서 base_footprint 실제 위치, 새로 추가).
2. **재생**: 같은 bag을 두 방식에 따로 넣는다(입력이 바이트 단위로 같음, Isaac과 GPU를 나눠 쓰지 않음).
   - Cartographer 구성: `map → odom` Cartographer, `odom → base_footprint` 바퀴 오도메트리.
   - cuVSLAM 구성: `map → odom`·`odom → base_footprint` 모두 cuVSLAM(적외선 스테레오, IMU 없음).
3. **조건**(초안): 조명 밝음·어두움 2가지 × 반복 3회. 경로는 출발 칸에서 미로를 돌아 출발 칸으로 돌아오는 한 바퀴(제자리 회전 포함, 속도는 V 시험에서 쓴 주행 방식).

## 3. 측정값과 예상 (실행 전에 적음)

| 측정값 | 정의 | 예상 |
|---|---|---|
| A1 위치 오차 RMSE (m) | 추정 `map → base_footprint`와 정답의 평면 거리, 0.1 s마다 | Cartographer ≤ 0.05, cuVSLAM 0.05~0.2(흰 벽판은 특징이 적음) |
| A2 마지막 위치 오차 (m) | 출발 칸으로 돌아온 순간 | Cartographer는 루프 폐합으로 작음, cuVSLAM은 누적 오차가 남음 |
| A3 헤딩 오차 RMSE (°) | 추정과 정답의 yaw 차 | 둘 다 ≤ 3° |
| A4 추적 끊김 (회) | cuVSLAM tracking lost 횟수 / Cartographer 스캔 매칭 실패 | 어두움 조건에서 cuVSLAM만 늘어남 |
| M1 지도 | Cartographer: 유령 벽 비율·벽 위치 오차·채움률(정답 = 미로 벽 단면). cuVSLAM은 점유 지도를 내지 않아 지도 비교에서 뺌 | Cartographer 벽 위치 오차 ≤ 3 cm |
| C1 계산 부담 | 재생 중 CPU 시간, 최대 메모리, GPU 메모리 | cuVSLAM은 GPU 메모리 약 1 GB, CPU는 Cartographer보다 작음 |
| C2 출력 지연 (ms) | 입력 stamp와 자세 출력 사이 | 둘 다 ≤ 100 |

## 7. 구현 (2026-10-27, `slam/`)

- `route.py`: layout.json 칸 벽으로 출발 칸 c00 → 24칸 모두 → c00 깊이 우선 순회(경유점 47, 34.5 m).
- `scene_slam.py`(L2 장면 바탕, 원본 그대로 둠): 월드 USD 열기, v12 조건, 팔 S0로 접은 뒤 출발, 정답 자세로 경유점 추종(제자리 회전 → 직진 0.2 m/s, 회전 최대 0.6 rad/s). 적외선 좌·우 640×480 30 Hz(실물 D435 적외선 K: fx = fy = 385.0128, cx 320.8596, cy 239.9280), 렌더 rgb → mono8(실물 Y8과 같은 형식, header 그대로). baseline은 USD 프레임 사이 거리로 재서 오른쪽 P[3]에 넣음.
  - **오도메트리는 바퀴 관절 속도로 계산**(엔코더와 같은 방식, 미끄럼 오차 포함). L2의 Isaac 계산 오도메트리는 차체 실제 움직임이라 정답과 같아 Cartographer에 유리하므로 쓰지 않는다.
  - 정답 자세는 ROS로 내지 않고 `truth.csv`(50 Hz)에만 쓴다.
- `run_record.sh`: robot_state_publisher + `ros2 bag record --use-sim-time`(mcap, zstd_fast, 수신 버퍼 16 MB 설정) + 장면. UDP RcvbufErrors 앞뒤, GPU 메모리 기록. GPU 잠금 `/tmp/lv2_gpu.lock`.
- 가정(실물과 다른 점): 적외선 영상은 가시광 렌더를 흑백으로 바꾼 것이다. 실물 D435 적외선 투사 점 무늬는 없다.
