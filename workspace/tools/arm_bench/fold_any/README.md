# 어느 자세에서 켜도 STOW 로 접기 — 경로 계산 (2026-11-18, 계산만 · 실물 확인 전)

왜: 예전에는 팔이 STOW (또는 DRIVE) 근처에 있어야만 bringup 이 켜지고 팔 정리가 움직였다 (11-16 실물 미션이 STOW 에서 0.23 rad 어긋나 멈춤).
이제 대기 범위를 관절마다 펌웨어 범위 전체로 넓히고 (`opencr.ros2_control.xacro`), 켜진 뒤 manipulator 가 정해진 순서로 STOW 로 접는다
(`manipulator.yaml` `startup.fold_to_stow` · `startup.fold_path`, `startup_stow.hpp` `parseFoldPath`).

모델: 팀 URDF `waffle_4wd_loaded.urdf` (B안 · 팔레트 v5 · 퍽 10 개) 의 충돌 형상, 팔 link3 ~ 집게 상자 ↔ 차체 · 팔레트 · 퍽 · 라이다 · 바퀴 겉면 점 (`../fold_clearance.py` 와 같은 계산).

## 1. 들어 올린 자세 FOLD_UP 고르기 (`up_candidates.py`)
J2 · J3 · J4 를 7 × 7 × 7 으로 놓고 J1 을 한 바퀴 (13 곳) 돌릴 때 가장 가까운 틈. 가장 좋은 것들이 **33.6 mm** (5 cm 이상은 5 cm 로 자름).
고른 값 `FOLD_UP = [J1 그대로, 0.0, −0.73, −1.60, 0, 0.923]`. 결과 `results/up_grid.txt` · `up_top.txt`.

## 2. 접기 순서 (`fold_any_check.py`, 시작 300 곳 · seed 1)
시작 자세 = 관절 한계 안 무작위 중 그 자리 자체는 닿지 않는 것. 판정 (계산 전에 정함): 경로 내내 최소 틈 ≥ 5 mm.

| 순서 (S = STOW, U = FOLD_UP) | 틈 ≥ 5 mm | 출발부터 5 mm 안인 14 곳 빼면 | 하위 5 % 틈 |
|---|---|---|---|
| **234U → 56S → 1S → 4S → 2S → 3S (채택)** | **273 / 300 (91.0 %)** | **95.5 %** | −4.2 mm |
| 56S → 234U → 1S → 4S → 2S → 3S | 267 / 300 (89.0 %) | — | −3.5 mm |
| 2U → 3U → 4U → 56S → … | 225 / 300 (75.0 %) | 78.7 % | −14.2 mm |
| 3U → 2U → 4U → 56S → … | 222 / 300 (74.0 %) | 77.6 % | −14.2 mm |
| FOLD_UP = [0, −1.60, 0] 로 바꾸면 | 0 / 300 | — | 마지막 J2 단계에서 집게 ↔ 바퀴 |

- 채택한 순서의 실패 27 곳은 **모두 첫 단계 (J2 · J3 · J4 를 들어 올릴 때)**, 대부분 집게가 차체 (static) 에 닿음 — 팔이 차체에 낮게 붙은 채 켜진 경우.
- 모든 경로의 최소 틈 중앙이 9.2 mm 인 것은 STOW 자세 자체의 틈 (#277 계산과 같음).
